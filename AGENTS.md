# AGENTS.md – Roots & Routes (Naše kořeny)

Genealogická webová aplikace: import GEDCOM, zobrazení předků na mapě (OpenLayers) a ve stromu, editace osob, slučování GEDCOM souborů, správa známých lokalit, uživatelé s oprávněními a více rodokmenů (datových základen).

- **Produkce:** https://nase-koreny.mikulik.com (Vercel, region `iad1`). Vercel nasazuje automaticky po každém pushi do `master` (Git integrace).
- **Repo:** https://github.com/davidmikulik/roots-and-routes, větev `master`
- **Jazyk:** UI, commity i komunikace s uživatelem jsou česky; identifikátory v kódu anglicky.

## Stack

Nuxt 3 (SSR + Nitro, preset `vercel`), Vue 3, TypeScript strict, Tailwind, OpenLayers 10 + proj4 (npm, jen v prohlížeči), `@vercel/blob` (private access).

## Tok dat

1. **Import** (`/gedcom` → `POST /api/gedcom/import`): server soubor naparsuje, doplní souřadnice z `known-locations.json` a uloží do složky vybrané datové základny (`databasePaths(db)` v `server/utils/access.ts`):
   - originál jako `<prefix>/current.ged`
   - naparsovaná data jako `<prefix>/parsed/current.json`

   Každá datová základna má jeden strom (`fileId = 'current'`). Původní strom z doby před účty je základna `main` s prefixem `uploads/gedcom`, nové mají `uploads/gedcom/databases/<id>`. Která základna se myslí, říká hlavička `X-Database` (bez ní výchozí základna uživatele, u návštěvníka veřejná).
2. **Načtení:** `useGedcomStore()` volá v `onMounted` **na každé stránce** `GET /api/gedcom/get` a přepíše jím store. Když server nic nevrátí, použije se (jen s oprávněním `read`) lokální kopie z IndexedDB (`roots-and-routes` / `gedcom` / klíč = id základny, uložený GEDCOM text). Po odhlášení se lokální kopie mažou.
3. **Editace / merge / smazání osoby:** store změní data lokálně, uloží GEDCOM text do IndexedDB a pošle `POST /api/gedcom/save` do základny, ze které strom načetl (`state.databaseId`, `authHeaders(state.value.databaseId)`).

## ⚠️ Důležité pasti

- **`GedcomFile` obsahuje `Map`.** `JSON.stringify(new Map())` vrací `{}`. Kdykoli `GedcomFile` putuje přes JSON (Blob, API odpověď, request body), **musí** projít přes `serializeGedcomFile` / `deserializeGedcomFile` z `utils/gedcom/serialize.ts`. Když se to zapomene, projeví se to takto: hned po importu se data zobrazí (mapy vznikly v prohlížeči), ale po přepnutí stránky je store prázdný, i když `GET` vrací správné `metadata.totalIndividuals`.
- **JSON z `Date` udělá string.** `deserializeGedcomFile` proto vrací zpět na `Date` pole `parsed`, `date1`, `date2`, `sortDate`, `earliestDate` a `latestDate`. Bez toho padá `convertToFamilyTree` / `convertToAppPerson` na `date.parsed.getFullYear is not a function`, takže `/tree` po načtení ze serveru nic nezobrazí. Kdo do typů přidá nové pole typu `Date`, musí ho doplnit do `DATE_KEYS` v `utils/gedcom/serialize.ts`.
- **`useGedcomStore()` vrací obyčejný objekt s `ComputedRef`.** Ani v šabloně se nerozbalí, takže piš `gedcomStore.hasData.value`, `gedcomStore.totalIndividuals.value` atd. Výraz `!gedcomStore.hasData` je vždycky `false`.
- Staré `parsed/*.json` z doby před opravou mají mapy uložené jako `{}`. `loadParsedGedcom` pro ně vrací `null`. `get.get.ts` při nekonzistenci (metadata > 0, mapa prázdná) zkusí znovu naparsovat originální `.ged`.
- `listUserFiles()` vypisuje celý prefix `uploads/gedcom`, tedy i `parsed/*.json`, `exports/*` a `known-locations.json`. Záložní větev v `get.get.ts` („nejnovější soubor“) proto může vybrat soubor, který není GEDCOM.
- **Anonymní režim je pro nepřihlášené a pro oprávnění `demo` vždy zapnutý** (`useAnonymize`: `!canRead || nastavení`). Ti navíc dostávají ze serveru jen anonymní kopii dat (viz další bod), takže `useAnonymize` u nich maskuje už anonymní data a od oprávnění `read` slouží jako volitelné zobrazení (např. při promítání). Nové místo, které zobrazuje jméno, datum nebo místo, musí projít přes `anon.name/date/place`.
- **Anonymní data ze serveru:** `GET /api/gedcom/get` bez oprávnění `read` na základně (návštěvník na veřejné základně, oprávnění `demo`) vrací kopii z `server/utils/anonymizeGedcom.ts` (iniciály, jen rok, bez míst, souřadnic, poznámek, zdrojů, adres a médií; zůstávají id, pohlaví, rodiny a typy událostí) a v odpovědi `data.anonymized: true`. Mapa je proto pro nepřihlášené prázdná. Odpověď má `cache-control: private, no-store` a `vary: Authorization, X-Database`. Store si to pamatuje ve `state.anonymized`: na anonymních datech nejde editovat, ukládat ani exportovat (`requireEditable`, `requireFullData`), jinak by se skutečný strom přepsal iniciálami. Po přihlášení, odhlášení, přepnutí základny nebo změně oprávnění store data sám znovu načte (jeden odpojený watcher na `adminAuth.dataKey`, ne při neuložených změnách), `refreshFromServer` si předem obnoví relaci z localStorage a starší odpověď nepřepíše novější. Nové pole v typech, které nese osobní údaj, přidej do anonymizace (výchozí je vynechat ho).
- **Bubliny (`app/components/HoverTip.vue`):** zobrazují se při najetí i při fokusu (klepnutí na telefonu) a hlídají okraj obrazovky. Bez `text` se vykreslí jen obsah. Roky života (celé datum) řeší `app/components/LifespanTips.vue`, použitá v tabulce i v detailu osoby; zeměpisné události (místo) se zobrazují jen v detailu; v anonymním režimu datum bublinu nemá a místo je nahrazeno textem „Skryto v anonymním režimu“. Datum se formátuje z textu GEDCOM (`utils/gedcom/dates.ts`), ne z `Date`, který se mezi časovými pásmy posouvá. Při testování v headless Chrome používej `scrollIntoView({ behavior: 'instant' })`, protože `html` má `scroll-behavior: smooth`.
- **Grafický strom (`/graph`):** rozložení počítá `relatives-tree` (jen pozice a spojnice), karty jsou naše HTML. Balíček má ES moduly bez přípon v importech, proto je v `nuxt.config.ts` `build.transpile: ['relatives-tree']` (bez toho spadne prerender a Node ho nenačte, ve skriptech použij `npx jiti`). Knihovna zobrazí děti *páru*: dítě s jedním známým rodičem by u rodiče s dalším partnerem zmizelo, proto `buildTreeNodes` vymýšlí neznámého partnera (`unknown-…`, není v souboru GEDCOM, na kartě „Osoba není zapsána“). Půlsourozenci se u kořene nezobrazují a druhý partner může být umístěn na okraji skupiny sourozenců. Objekty d3 jsou v proměnných mimo reaktivitu. Plátno sleduje změnu kořene i bez změny pozic (členové jedné rodiny mají stejné rozložení). Při změně `treeGraph.ts` spusť `npm run check:graph -- <get.json>` (stáhni `GET /api/gedcom/get` s `ADMIN_API_TOKEN` jako Bearer a případně `X-Database`; bez něj přijdou anonymní data, kterým chybí místa a celá data).
- **Jména:** `names[].full` je jméno pro zobrazení **bez lomítek** (`Jan Mikulik`). Rozklad řádku GEDCOM `NAME` i zpětný zápis s lomítky (`Jan /Mikulik/`) řeší `utils/gedcom/names.ts` (`parseGedcomName`, `nameToGedcom`), parser i export ho používají. Data uložená před touto opravou se čistí při načtení v `deserializeGedcomFile`. Lomítka do zobrazovaných jmen nikdy neskládej. **Rodné jméno a jméno po sňatku:** osoba může mít víc záznamů `NAME`; jméno s `TYPE married` je jméno po sňatku, první jiné je rodné (`birthNameOf`, `marriedNameOf`, `primaryNameOf` v `names.ts`). Parser čte `TYPE`, `GIVN`, `SURN` a `_MARNM` z MyHeritage (příjmení po sňatku pod rodným jménem) převede na samostatné jméno `married`; export ho zapíše standardně jako `1 NAME` + `2 TYPE married`. Jméno osoby se všude zobrazuje přes `useAnonymize().personName(osoba)`: „Marie Dvořáková (roz. Nováková)“ (EN „née“), v anonymním režimu jen iniciály jména, pod kterým se osoba zobrazuje. Bez i18n (`AppPerson.fullName`, `displayName`) se místo „roz.“ píše genealogické `*`. Anonymní data pro návštěvníky obsahují jen toto jedno jméno. **Jméno a příjmení (rodové jméno):** editor má zvlášť *Jméno*, *Příjmení (rodné)* a *Příjmení po sňatku* (`IndividualDraft.givenName/surname/marriedSurname`); jméno po sňatku má stejné křestní jméno. `savePerson` skládá `given`/`surname` a `full` (`joinNameParts`), nezměněné jméno ponechá celé (přípona „ml.“, typ). Jméno bez lomítek z importu rozdělí `namePartsOf` (poslední slovo = příjmení). Vyhledávání (`nameMatches`: každé slovo dotazu začíná jméno, rodné příjmení nebo příjmení po sňatku, bez diakritiky, v libovolném pořadí) a řazení (`nameSortKey`: příjmení, jméno; bez příjmení na konec) jdou přes `useAnonymize().matchesName/sortKey/surnames`, které v anonymním režimu pracují jen se zobrazenými iniciálami. Strom má filtr *Rodové jméno* (rodná i po sňatku, s počty). Výběr osoby psaním (jméno, příjmení, rok narození; šipky a Enter) je společná komponenta `app/components/PersonPicker.vue` pro grafický strom (osoba uprostřed) i mapu (filtr osob; výběr osoby přepne rozsah na „jen osoba“, zrušení zpět na všechny). Detail osoby na mapě má tlačítko *Vybrat osobu* (vyplní tento výběr), detail v grafickém stromu odkaz *Vybrat na mapě* (`/map?person=<id>`, mapa ho použije jednou po načtení stromu). Nové dítě a sourozenec dostanou příjmení otce, nový otec příjmení dítěte (`relationDraft`). Duplicity při slučování porovnávají jméno a příjmení zvlášť. Uložená data naparsovaná dřív `_MARNM` nemají: doplní je jednorázově Nastavení → Data → „Převzít jména po sňatku“ (`POST /api/admin/married-names`, `utils/gedcom/marriedNames.ts`) z původního `current.ged`, jen osobám se stejným id a rodným jménem a bez jména po sňatku; `apply: false` jen počítá, `apply: true` nejdřív zazálohuje.
- **Neznámé značky GEDCOM nejsou události.** Parser dřív z každého neznámého řádku první úrovně osoby udělal „událost“. Z MyHeritage tak měla každá osoba falešné události `_UPD` (čas úpravy, např. `12 OCT 2026 15:13:37 GMT -0500`), `_UID` a `RIN` a v editoru se ukazovaly s prázdným typem. Teď jdou neznámé řádky do `userData.extraTags` (`{ tag, value }`, podřízené řádky jako `2 DATE` u `CHAN` se přeskočí) a `writeGedcom` je zapíše zpátky beze změny. Seznam typů událostí je v `utils/gedcom/eventTypes.ts`. Hodnota na řádku události není datum: `1 DEAT Y` znamená jen „zemřel“, `1 OCCU Truhlář` má text v popisu a datum přichází jen z `2 DATE`. Data uložená starým parserem čistí při načtení `deserializeGedcomFile` (`cleanFakeEvents`, `cleanEventLineValue`): zahodí i „datum“ nebo popis události, který je identifikátorem MyHeritage (`MH:I500003`, 32místné `_UID`) nebo časovým razítkem (`_UPD`, obsahuje čas). Po dalším uložení zmizí i ze serveru. Parser bere `DATE`, `PLAC`, `NOTE` atd. jen jako přímé podřízené řádky události (úroveň 2), takže datum citace zdroje (`2 SOUR` / `3 DATA` / `4 DATE`) datum události nepřepíše; souřadnice (`4 LATI/LONG`) se čtou z libovolné hloubky.
- **Novinky a O aplikaci se aktualizují s každou změnou, kterou uživatel uvidí** (nová funkce, změna chování, oprava). Obě místa vždy, ve stejném commitu jako změna:
  1. **Novinky** (`utils/releaseNotes.ts`, `RELEASE_NOTES`, nejnovější první, česky i anglicky, položky `new` / `improved` / `fixed`, srozumitelně pro uživatele, bez technických pojmů). Nové vydání = nová položka na začátku a stejná verze v `package.json` (`version`); drobnost může jít do posledního ještě nenasazeného vydání. `npm run check:release` ověří shodu verzí, pořadí a oba jazyky.
  2. **O aplikaci** (Nastavení → O aplikaci, `app/pages/settings.vue`, texty `settings.about.*` v `i18n/settings.ts`): seznam funkcí (`settings.about.f1–f4`) a použité technologie (`settings.about.built`) musí odpovídat aktuální aplikaci. Když funkce přibude, změní se nebo zmizí, uprav i tyto texty.

  Novinky se zobrazují **jen v O aplikaci** (novinky aktuální verze, `ReleaseNotesList.vue`) a na stránce `/release-notes` (všechny verze, odkaz z O aplikaci). Na úvodní stránku ani do patičky nepatří.
- **Číslo a čas buildu:** `nuxt.config.ts` je při každém buildu (i při startu dev serveru) spočítá do `runtimeConfig.public.build`: `number` je čas buildu v UTC ve tvaru `YYYYMMDD.HHMM`, `commit` je z `VERCEL_GIT_COMMIT_SHA` (na Vercelu) nebo z gitu, `version` z `package.json`. Zobrazuje se v Nastavení → O aplikaci. Čas se vykresluje až v prohlížeči, protože server neví, v jakém časovém pásmu je návštěvník (jinak by Vue hlásilo nesoulad při hydrataci).
- **Mapa (OpenLayers):** stránka `app/pages/map.vue` drží filtry, výběr a panel. Samotná mapa je komponenta `app/components/EventMap.client.vue` (jen v prohlížeči, kvůli prerenderu), objekty OpenLayers jsou mimo reaktivitu. Pohled je ve Web Mercatoru. Vrstvy jen v S-JTSK (EPSG:5514: vojenská mapování a ortofoto z 50. let od CENIA, krajské císařské otisky JČ, JMK a MSK) OpenLayers přepočítá v prohlížeči (`proj4` + `register`). Katalog vrstev s mřížkami WMTS je `utils/map/layers.ts`, výběr podkladu, historické mapy, průhlednosti, historických názvů a překryvů (katastrální mapa, RÚIAN) se ukládá do Nastavení (`settings.map.baseLayer/historicLayer/historicOpacity/placeNames/extraLayers`). Císařské otisky tří krajů jsou jedna volba `cio` (skupina vrstev `kind: 'group'`, stará id `cio-jc/jmk/msk` převádí `LEGACY_HISTORIC_LAYER_IDS`). Služba JMK vrací mimo kraj bílé dlaždice, proto `whiteIsEmpty` zprůhlední čistě bílé pixely (papír map je krémový), jinak by v pohraničí zakryla jihočeské otisky. Značky se kreslí na plátno (kruh + emoji), nejsou to prvky DOM. Shluky dělá `ol/source/Cluster`: klepnutí na shluk přiblíží, a když nejde rozdělit (stejné místo nebo nejvyšší přiblížení), ukáže seznam událostí (`data-event-chooser`). Pod seznamem jsou odkazy na listy archivu ČÚZK u míst těchto událostí (prop `archiveMapsFor`, od oprávnění `read`, v anonymním režimu prázdné). Pravé tlačítko (na Androidu dlouhé podržení, na iOS nefunguje) ukáže GPS souřadnice bodu (`data-map-context`, klepnutí je zkopíruje do schránky), pod nimi odkazy „Otevřít v …“ do jiných map (Mapy.com, Google Maps; další služba = položka v `utils/map/externalMaps.ts`) a pod nimi odkazy na listy míst značek pod kurzorem. V komponentě `.client` může být odkaz na prvek v `onMounted` ještě prázdný, proto `whenElement()`. Katalog se naučí všechna místa ze souboru, i se souřadnicemi, pokud je soubor má. Položka katalogu bez souřadnic je ze souboru dostane, existující souřadnice v katalogu zůstanou (`learnKnownLocations`). `unresolved` jsou místa, která ani potom nemají souřadnice.

Neznámé místo se přidá do katalogu, se souřadnicemi, pokud jsou vyplněné. Souřadnice, které se liší od katalogu a osoba je před úpravou neměla (porovnává se `locationStamp` před a po), se zapíšou do katalogu a **přepíšou se u všech událostí se stejným místem**. Místo, které souřadnice dostane poprvé, je dá jen událostem, které žádné nemají. Souřadnice, které osoba měla už před úpravou a liší se od katalogu, se nemění.   - **Admin → Známá místa → Synchronizovat se stromem** (`syncKnownLocations`, po potvrzení) synchronizuje obousměrně a vezme i neuložené úpravy v tabulce. Strom → katalog: chybějící místa se přidají i se souřadnicemi a položky bez souřadnic je dostanou (`learnKnownLocations`). - **Odkazy osoby (editor v `/tree`):** libovolný počet, každý s povinnou adresou i popisem (`saveLinks` ve storu jinak uložení odmítne). V GEDCOM je každý odkaz záznam `0 @M1@ OBJE` (`1 FILE`, pod ním `2 FORM` a `2 TITL`) a osoba na něj odkazuje `1 OBJE @M1@`. Obyčejný odkaz má `FILE` = webová adresa a `FORM url`. Tlačítko **Zkopírovat** pošle adresu na `POST /api/media/copy`: server soubor stáhne (jen `http(s)`, žádné adresy soukromých sítí ani po přesměrování, max. 20 MB, jen obrázky JPG/PNG/GIF/WEBP a dokumenty PDF/TXT/RTF/DOC(X)/ODT/XLS(X)/ODS podle `Content-Type`, případně přípony) a uloží ho do Blobu. Záznam pak má `FILE media/<uuid>.<ext>`, `FORM` podle typu a původní adresu ve vlastní značce `1 _URL`. Kopie jsou soukromé, prohlížeč je stahuje s tokenem. V detailu osoby se přílohy zobrazují stejně jako webové odkazy (`<a target="_blank">` se stejnou třídou). Kopie stažená z webové adresy má dva odkazy: popis vede na původní adresu, za ním „příloha“ na kopii. Soubor ze schránky (bez adresy) má popis jako odkaz na kopii. Jak to funguje: `tree.vue` je stáhne, když detail přílohy ukazuje (`fetchStoredMedia`), a odkáže na ně `blob:` URL. Obrázky, PDF a TXT se otevřou na nové kartě, ostatní dokumenty se stáhnou s názvem podle popisu (`download`). Při změně osoby nebo odchodu ze stránky se URL uvolní. V editoru „Otevřít kopii“ používá `openStoredMedia`. **Vložit ze schránky** (a Ctrl+V, když je kurzor v řádku odkazu) pošle soubor na `POST /api/media/upload` (tělo = soubor, typ v `Content-Type`, původní jméno v `?name=`). Tlačítko přes `navigator.clipboard.read()` umí jen obrázek, protože prohlížeče jiné soubory schránkovému API nedají. Dokument zkopírovaný v průzkumníku souborů projde jen přes Ctrl+V (`clipboardData.files`). Vercel přijme v jednom požadavku nejvýš 4,5 MB, proto je limit 4 MB: větší obrázek klient převede na JPEG (`shrinkImage`, případně ho zmenší), větší dokument odmítne. Odkaz s uloženým souborem nepotřebuje adresu, popis je povinný vždy. Změna adresy zruší vazbu na kopii jen tehdy, když byla kopie stažená z původní adresy (`copiedFrom`). Soubor vložený ze schránky zůstane. Odebraný odkaz smaže záznam `OBJE`, pokud ho nepoužívá nikdo jiný, ale soubor v Blobu zůstane (nemazat dřív, než se změna uloží). **Zálohy** (`server/utils/backups.ts`) ukládají k `<id>.ged` i kopie všech příloh, na které strom odkazuje, do `backups/<id>/media/<name>`. Kopíruje se přes `copy()` přímo v Blobu, nic se nestahuje. Chybějící příloha zálohu nezastaví, jen se zaloguje. Obnova vrátí do `media/` přílohy, které tam chybí. Promazání starých záloh maže i jejich přílohy. `listBackups` vrací i počet příloh (`attachments`) a velikost včetně nich. `list()` z Blobu vrací max. 1000 položek na stránku, proto `listAll` stránkuje. **Export** (`downloadGedcom`) je bez příloh obyčejný `.ged`, s přílohami ZIP ve struktuře GEDZIP (GEDCOM 7): `gedcom.ged` + `media/<name>`. Sestavuje ho prohlížeč přes `fflate` (načítá se až při exportu), přílohy stahuje s tokenem a ty, které se stáhnout nepodaří, ohlásí. Serverový `/api/gedcom/export` přílohy neobsahuje. Anonymní data pro návštěvníky odkazy nemají. V detailu osoby se jako odkaz vykreslí jen `http(s)` adresa, jinak text (kvůli `javascript:` z importu). Odkazy a přílohy v detailu vykresluje společná komponenta `app/components/PersonLinks.vue` (Strom, detail osoby na mapě a v grafickém stromu přes `PersonDetail.vue`); přílohy stahuje s admin tokenem jako `blob:` URL a v anonymním režimu odkazy skryje.

V GEDCOM je to `2 OBJE @M1@` pod údajem: `NAME` (`GedcomName.multimediaLinks`), `SEX` (`GedcomIndividual.sexLinks`), událostí (`GedcomEvent.multimediaLinks`, i `MARR` rodiny). Citace záznamů `SOUR` pod událostmi (`2 SOUR @S1@` / `3 PAGE`) parser čte do `GedcomEvent.sourceCitations` a zápis je vrací. Editor odkazuje na odkazy klíčem `LinkDraft.key` (u uložených = id), koncept nese `IndividualDraft.sources` (jméno, jméno po sňatku, pohlaví, narození, úmrtí, sňatek) a `IndividualEventDraft.sources`; výběr je `app/components/SourcePicker.vue` („Nový odkaz nebo příloha…“ přidá řádek do odkazů). `savePerson` nejdřív uloží odkazy (`saveLinks` vrací `idByKey`), pak údajům nastaví id a nakonec `pruneMedia` smaže záznamy `OBJE`, na které už nic v celém stromu neukazuje (`mediaReferences`). Detail ukazuje `app/components/PersonSources.vue` s čísly odkazů z `PersonLinks.vue`. **Žije:** zemřelý = událost `DEAT`, i prázdná (zápis `1 DEAT Y`); kdo ji nemá, žije (rozhodnutí uživatele: osoby z importu bez úmrtí se berou jako žijící). Editor má `IndividualDraft.livingStatus` jen `living`/`deceased`. Importovanou značku `1 _LIVING Y` parser čte do `GedcomIndividual.living` a zápis ji vrací, `savePerson` ji ale maže (není potřeba). Pole úmrtí se v editoru ukazují jen u zemřelého. Anonymní kopie zdroje ani `living` nemá (whitelist v `anonymizeGedcom.ts`). **Věk** počítá `personAge` v `utils/gedcom/age.ts` (bez úmrtí: dnes − narození, zemřelý: úmrtí − narození; chybí-li potřebné datum, „?“; neúplné nebo nejisté datum = `approximate`) a zobrazuje `app/components/PersonAge.vue` u každé osoby: detail osoby, seznam, zobrazení stromu a grafu v `/tree`, karty `/graph` (`compact` = jen číslo, „?“ s bublinou).
- **`setFile` musí zachovat `fileId`.** Úpravy ho volají bez id. Kdyby ho vynuloval, `saveToServer` by se tiše přeskočil a změny by se po dalším načtení stránky ztratily.

## Příkazy (v `roots-and-routes/`)

```bash
npm run dev          # http://localhost:3000, vyžaduje .env s BLOB_READ_WRITE_TOKEN
npx vue-tsc --noEmit # typecheck (celý projekt má i starší chyby, filtruj změněné soubory)
npm run build        # nuxt build → .vercel/output; nejlepší rychlé ověření
npm run lint
npm run check:release # novinky: verze = package.json, pořadí, oba jazyky
npm run deploy       # vercel --prod; jen když automatický deploy po pushi neproběhl a uživatel ho výslovně vyžádá
```

Projekt nemá automatické testy. Změnu ověř buildem, typecheckem změněných souborů, případně ručně v `npm run dev`.

## Konvence

- Commit messages: krátké, buď česky, nebo ve tvaru `fix: …` / `improve: …`.
- Commituj a pushuj jen na výslovný pokyn. Push do `master` = nasazení na produkci (Vercel ho spustí sám), proto po pushi ověř, že produkce běží na novém commitu (Nastavení → O aplikaci). Ruční `npm run deploy` jen na výslovný pokyn, když automatický deploy neproběhl. Složka `roots-and-routes/` není propojená přes `vercel link`, takže se CLI zeptá na nastavení projektu: neodpovídej za uživatele a ověř s ním, který projekt vybrat.
- Sdílenou logiku pro klienta i server dávej do `utils/` (auto-import přes `imports.dirs`). Server-only kód patří do `server/utils/`.
